# Спринт 2 — команда 03
**Группа:** ТС112-26  
**Кейс:** А — Учебная служба поддержки  
**Цель:** Для 20 студентов учебного кабинета подготовить учебный порядок обработки обращений, чтобы решить проблему потери заявок в чатах и упорядочить оказание помощи.  
**Границы:** Проект рассчитан на 2 учебных дня. Разработка полноценного ПО, интеграция с реальными ИС и использование настоящих персональных данных в объём проекта не входят.  

## Роли в команде
* У1 — @ваш_логин_координатор — координатор (Следит за временем и распределением нагрузки)
* У2 — @логин_аналитика — аналитик (Выделяет требования и границы кейса)
* У3 — @логин_технаря — технический специалист (Проверяет состав задач и зависимости)
* У4 — @логин_проверяющего — проверяющий (Отвечает за критерии приёмки)

## Правила работы команды
В работе одновременно находится не более двух карточек. При неполном результате карточка остаётся в работе. Ошибки после проверки возвращают задачу в работу. В каждой карточке один ответственный и другой проверяющий.

## Журнал изменений (Шаг 10)
* **Изменение:** Преподаватель запретил собирать фамилии. Обращения нужно учитывать только по учебному ID.
* **Затронуты:** Т01 (Требования к форме) и Т02 (Разработка формы).
* **До изменения:** В форме планировались поля ФИО и контакты.
* **После изменения:** Из полей формы полностью исключены персональные данные (фамилии), добавлен обязательный сбор Учебного ID студента.
* **Причина:** Требование преподавателя по защите персональных данных.
